# Domain Docs

This project uses a **single-context** layout.

When you need to understand the project's domain language, glossary, and core concepts, read the file `CONTEXT.md` at the root of the repository.

When you need to understand the project's past architectural decisions, read the markdown files in the `docs/adr/` directory.

## Updating rules

- If you encounter a new domain term, clarify its definition with the user and update `CONTEXT.md` immediately. Do not wait for the end of the conversation.
- If you make an architectural decision that is hard to reverse, surprising, and involves a real trade-off, propose creating a new ADR in `docs/adr/`.
